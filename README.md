### S02: The QA Journey

S02 explains how I approach quality assurance as a continuous lifecycle rather than a final testing activity. It follows the work from understanding requirements through planning, test design, readiness, execution, defect investigation, automation, and release validation.

1. **Requirement Analysis & Understanding** - Review business requirements, functional specifications, user stories, acceptance criteria, business rules, and user expectations. Identify gaps, ambiguity, dependencies, and potential product risks, then clarify expected behaviour with relevant stakeholders.
2. **Test Planning & Strategy** - Define testing objectives, scope, approach, priorities, dependencies, effort, and timelines. Establish a risk-based strategy that directs testing attention toward critical functionality and important user journeys.
3. **Test Scenario & Test Case Design** - Prepare structured test scenarios and test cases covering positive, negative, boundary, and alternate conditions. Apply equivalence partitioning and boundary value analysis, prepare test data, and maintain requirement traceability through an RTM.
4. **Environment & Test Readiness** - Confirm that the application build and test environment are available and usable. Validate configurations, access permissions, accounts, and test data, then perform initial smoke checks to assess build stability.
5. **Functional Testing & Execution** - Execute functional, integration, system, and end-to-end test cases. Validate interface elements, navigation, forms, business rules, and workflows, supported by regression, exploratory, and negative testing.
6. **Defect Reporting & Management** - Record defects with clear reproduction steps, expected and actual results, and supporting screenshots or video evidence. Assess severity and priority, collaborate with developers, track fixes, and perform retesting and regression validation.
7. **Automation & Regression Testing** - Identify repeatable and business-critical scenarios that benefit from automation. Build and execute end-to-end checks with Playwright, review reports, investigate failures, and maintain dependable automated coverage.
8. **Final Validation & Release Readiness** - Complete final regression and sanity testing, verify important fixes, review test coverage and outstanding risks, and prepare test summary information to support release-readiness recommendations.

**QA lifecycle flow:** Understand → Plan → Design → Prepare → Execute → Investigate → Optimize → Deliver.

**Quality philosophy:** Quality is a continuous responsibility. I focus on preventing defects early, identifying risks before they affect users, validating realistic scenarios, and improving testing practices throughout delivery.

## ⚙️ Getting Started
### Prerequisites
- **Node.js:** Node.js 20.19+ or 22.12+ recommended for current Vite tooling.

- **npm:** Included with Node.js.

- **Git:** Required to clone the repository.

### 1. Clone the repository
```bash

git clone https://github.com/lifeofthecoders/Sumit_Panchal_QA_Portfolio_Series.git

cd Sumit_Panchal_QA_Portfolio_Series

```

### 2. Install dependencies
```bash

npm ci

```

Use `npm install` only when you intentionally need to update or regenerate the dependency lockfile.

### 3. Start the development server
```bash

npm run dev

```

Open the local URL shown in the terminal. Vite normally uses:

```text

http://localhost:5173/Sumit_Panchal_QA_Portfolio_Series/

```

### 4. Build and preview
```bash

npm run build

npm run preview

```

The production site is generated in the `dist/` directory.

### Available Scripts
| Command | Purpose |
|---|---|
| `npm run dev` | Start the local Vite development server |
| `npm run build` | Run TypeScript project builds and create the production bundle |
| `npm run preview` | Preview the production bundle locally |
| `npm run images` | Run the repository image-processing script |

## 🚀 Deployment
This repository is configured for **GitHub Pages** with the Vite base path:

```ts

base: '/Sumit_Panchal_QA_Portfolio_Series/',

```

A GitHub Actions workflow is located at:

```text

.github/workflows/deploy.yml

```

The workflow installs dependencies with `npm ci`, runs `npm run build`, and deploys the generated `dist/` directory to GitHub Pages.

### Deployment Steps
1. Push the latest source changes to the repository's `main` branch.

2. Open the repository on GitHub.

3. Go to **Settings → Pages** and confirm GitHub Actions is selected as the build and deployment source.

4. Check the **Actions** tab for the deployment workflow.

5. Open the published website and verify the home page, project detail URLs, images, resume, and browser icon.

The configured public URL is:

[GitHub Repository](https://github.com/lifeofthecoders/Sumit_Panchal_QA_Portfolio_Series) · [Live Portfolio](https://lifeofthecoders.github.io/Sumit_Panchal_QA_Portfolio_Series/)

If the favicon appears unchanged immediately after deployment, perform a hard refresh (`Ctrl + Shift + R`) or clear the browser's cached site icon. Browser favicon caches can persist independently of the page cache.
